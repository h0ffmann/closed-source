Rewrite the prose in $ARGUMENTS to ASD-STE100 Simplified Technical English (issue 9). If the
argument is a path or a glob, edit those files in place. If it is text, give the rewritten text
only.

Change only the prose. Do not change these: code blocks, inline code, commands, file paths, URLs,
link targets, table structure, headings' anchors that other files link to (`{#sec:...}`,
`{#tbl:...}`), YAML keys, names of products, labels and flags, numbers and their units, quotations,
citation markers (`[@key]`, `@key`, `[-@sec:...]`) and the markers `**[ANALYSIS]**` and
`**[AUTHOR ANECDOTE: ...]**`.

## Rules

Words

- Use one word for one meaning, and the same word each time. Use the approved STE meaning
  ("test" is a verb and a noun; "check" is a verb). Do not use synonyms for variety.
- Technical names and technical verbs are permitted (`flake`, `lock file`, `tag`, `to rebase`).
- Use simple verb forms: the infinitive, the imperative, the simple present, the simple past and
  the future. Do not use other tenses. Do not use the -ing form as a verb or a noun.
- Do not use phrasal verbs ("set up" becomes "configure", "find out" becomes "find").
- Keep the articles ("the", "a") and the short words that make the sentence clear.
- Do not use more than three nouns in a cluster. Break a long cluster with a preposition.

Sentences

- Procedural sentences (instructions): 20 words or fewer. Descriptive sentences: 25 words or
  fewer.
- One topic in a sentence. One instruction in a sentence, unless two actions occur at the same
  time.
- Write instructions in the imperative ("Run `just release`"). Put a condition first ("If the tag
  exists, stop").
- Use the active voice in procedures. Use the passive voice in descriptions only when the agent
  is not known or not important.
- Put a warning or a caution before the step it applies to, and say the risk and its result.

Paragraphs

- One topic in a paragraph. Not more than six sentences in a paragraph.
- Write a sequence of steps as a numbered list, one step in an item.

## How to work

1. Read the whole text first. Find the terms it uses for the same thing, and pick one term for
   each.
2. Rewrite sentence by sentence. Do not remove a fact, a condition, a number or a reference.
   If a sentence says something you cannot keep in STE, keep the fact and simplify the words.
3. Check each sentence against the word count and the rules above.
4. Report the files you changed, and each place where you kept a sentence outside the rules, with
   the reason (for example, a quotation).

This repository's AGENTS.md wins over these rules where they disagree. Scientific papers are not
procedures: do not rewrite them unless the argument names them. A paper's STE text lives in
`papers/<slug>/prose-ste/` next to its original `prose/`, which stays as written; log each pass in
`papers/<slug>/STE100.md`. `just` builds both, as `pdf/<slug>.pdf` and `pdf/<slug>-ste.pdf`.
